## Training

Run on cluster62 GPU0 using `da_stronger_train.py` and `make_exp_subset.py`. The supervised hit loss used all MC types, with signal defined as `label != 0`. The adversarial domain loss used only `muatm` MC versus experiment, avoiding forced matching of neutrino and experimental event populations. Both sources had a raw ≥8-hit / ≥2-string cut. Experimental data were normalized to MC statistics.

1. Warm-start from the good DA checkpoint. Enable a true Boolean transformer padding mask and masked event-level domain pooling. Train 1,000 steps with two discriminator updates per encoder update, discriminator LR `1e-3`, encoder LR `5e-5`, adversarial weight `0.5`, batch size 16 MC supervised plus 12 MC-muatm / 12 experimental domain events. This is `runs/masked_proper_l5_lr5e5/step_1000.ckpt` on cluster62.
2. Starting from that checkpoint, select domain events by the model's predicted ≥8 signal hits on ≥2 strings at score 0.5. Fine-tune 600 steps with MC hit cross-entropy plus `0.2 ×` a differentiable 128-quantile approximation to 1D Wasserstein distance between MC-muatm and experimental hit scores. Encoder LR `1e-5`, no discriminator updates. This is the delivered checkpoint.

The signal-weighted domain-head experiment was **rejected**: its hit precision and W1 deteriorated. A head-only MC calibration did not materially recover quality. Training logs/checkpoints remain under `/home/plotnikovgp/tmp/baikal-da-strong-20261015/` on cluster62.

## Independent test

For each test half, train a fresh standardized logistic-regression probe on **frozen** encoder features from 5,000 MC `muatm` validation events plus 5,000 experimental validation events. Evaluate on disjoint 5,000 MC validation events and 5,000 experimental **test** events. The two test halves use MC validation offsets 5,000 and 10,000, and experimental test offsets 0 and 5,000; neither was used for model training. Features are masked means of final hit embeddings. All metrics below use the two-class softmax signal probability, not the legacy `sigmoid(logit_1)` convention in `generate_report.py`.

As in the original report, post-cut W1 pools the scores of **all hits inside accepted events**; it does not retain only hits above the score threshold. For the fixed-cohort comparison, the accepted events are the intersection of the two models' event selections.

## Reproduction and usage

The scripts at repository root are `make_exp_subset.py`, `da_stronger_train.py`, `da_stronger_holdout.py`, and `da_stronger_bootstrap.py`. The last two implement the independent probe and the paired fixed-cohort comparison. The input HDF5 source and checkpoint paths are explicit at the top of the scripts and can be overridden by their CLI options. The exact JSON results are checked in under `da_output_w1_20261015_results/` and also remain on cluster62 at:

To load on cluster63 from this branch's checkout:

```python
import torch
from pytorch_training.models.encoder import EncoderDomainAdaptation

model = EncoderDomainAdaptation(
    in_features=5, hidden_size=128, num_layers=5,
    dim_feedforward_size=512, n_heads=1, out_size=2, dropout_p=0.0,
    num_domains=2, domain_classifier_hidden_size=128,
    domain_classifier_layers=2, gradient_reversal_alpha=1.0,
    aggregate_output=False, proper_key_padding_mask=True,
    masked_domain_pooling=True,
)
state = torch.load("pytorch_training/checkpoints/noise_sig_experiments/"
                   "da_output_w1_20261015/best.ckpt", map_location="cpu")
model.load_state_dict(state, strict=True)
model.eval()
with torch.no_grad():
    hit_logits, _ = model(features, mask)  # [batch, hits, 5], [batch, hits] bool
    signal_probability = hit_logits.softmax(-1)[..., 1]
```

This checkpoint was verified to load with `strict=True` and run CPU inference in the cluster63 checkout. It **requires the updated code**: older `encoder.py` silently ignores the new mask flags and would produce different predictions.
